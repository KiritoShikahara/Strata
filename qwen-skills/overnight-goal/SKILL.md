# overnight-goal

ユーザーはこれから不在になる。ゴールは **$ARGUMENTS**。
引数が空なら、ゴールは「各セッションの残タスクをすべて完了する」とみなす。
引数に `上限 8h` / `max 90m` などの時間があれば、それを安全上限とする。なければ上限は 8時間。

## 開始時

1. `date +%s` などで開始時刻を取得して記録する。
2. ゴールを **検証可能な完了条件** に書き換えて記録する（例: 「`npm test` が exit 0」「`tasks.md` の未チェック項目が0」）。
   - 曖昧な部分は、これまでの依頼内容・リポジトリの規約から最も妥当な解釈を選び、その解釈を報告に明記する。ユーザーに質問して止まらない。
3. 完了条件を満たすためのサブタスクを洗い出す（タスク機能があれば1項目1ステップで登録）。

## 指示

1. サブタスクを、**これまでの依頼・承認の範囲で**自律的に1件ずつ進める。
2. 各サブタスク後にテスト/ビルドで検証し、完了条件を再チェックする。
3. 利用可能なゴール設定・定期確認（ループ / スケジュール / タスク機能など）で、停止した未完了セッションを再開する。
4. 行き詰まったら同じ方法を繰り返さず、別の解決方法へ切り替える。同じ失敗が3回続いたら、そのサブタスクを保留リストへ移す。
5. ユーザーの入力待ちになる項目は保留リストに入れ、他の作業を進める。
6. 重要な変化（ゴール達成・ブロック・失敗・危険の検知）だけ通知する。逐次報告はしない。
7. **ゴール達成前にターンを終えない**。「待機中」と書いて応答を終えると、そこでセッションが止まる。待ちが必要なら `sleep 60` などで待ってから再チェックする。

## 終了条件（いずれか1つで終了し、報告を1回だけ出す）

- **達成**: 完了条件をすべて検証で満たした。達成後に追加作業はしない（品質向上は `/overnight` の役割）。
- **ブロック**: 残りのサブタスクがすべて保留リストにあり、進められる作業がない。
- **上限到達**: 開始から安全上限が経過した。新しい作業を始めず報告する。

## 安全上の制約（自律中も必ず守る）

- 既に承認された範囲を超える破壊的・外部向け操作（データ削除、force push、公開、メッセージ送信、システムへのインストール、課金発生）は実行せず保留する。
- ゴール達成のためにテストを弱める・期待値をハードコードする・検証をスキップすることはしない。
- 秘密情報を出力・コミットしない。
- 検証できなかった変更は、その旨を報告に明記する。

## 終了時の報告

1行目に結果（達成 / ブロック / 上限到達）と経過時間を書き、続けて以下の3区分で簡潔に報告する。各項目に `file:line` やコミットIDを添える。

1. **完了事項** — 何が動くようになったか（完了条件の検証結果つき）
2. **残タスク** — 未着手・途中のもの（次の一手つき）
3. **保留理由** — ユーザー入力待ち・承認待ち・失敗の原因、およびゴールの解釈
